FairToy · child-labour exposure

Один флаг на поставщике показывает все затронутые игрушки

Финишер отмечает поставщика или его фабрику. Приложение проходит цепочку в обратную сторону и для каждой игрушки показывает, затронута ли она и через какую деталь.

BOM (Bill of Materials, спецификация) — это список деталей игрушки с количеством, файл bill_of_materials.csv. В BOM указана только деталь, без источника. Поэтому для детали с двумя поставщиками нельзя сказать, от кого она пришла.

Правила

Три уровня статуса

Статус считается снизу вверх: источник, потом деталь, потом игрушка. Это чистая функция evaluate(catalog, active_flags): без побочных эффектов, полностью покрыта тестами.

1. Источник детали

Пара «деталь + фабрика». Поставщик определяется по фабрике.

СтатусКогда
flaggedфлаг на весь поставщик или на эту фабрику
supplier_riskфлаг на другие фабрики того же поставщика
cleanу поставщика нет активного флага

2. Деталь

У детали n источников, из них f флагнутых. BOM не говорит, какой источник использован.

СтатусКогда
confirmedf = n: какой источник ни возьми, он флагнут
potential0 < f < n: возможно, деталь пришла от флагнутого
supplier_riskf = 0, но есть источник supplier_risk
cleanиначе

Так это выглядит в реальном parts.csv: одна деталь, две строки. Таких деталей 22.

part_id,  part_name, supplier_id, factory_id, unit_cost_usd
PRT-0235, LED array, SUP-022,     FAC-0104,   4.4
PRT-0235, LED array, SUP-002,     FAC-0008,   4.18

3. Игрушка

Худший статус среди деталей её BOM.

toy = max(part₁, part₂, …)
confirmed › potential › supplier_risk › clean

Для оценки экспозиции к статусу добавляются деньги: revenue = price × units_per_year по каждому листингу финишера.

Почему флаг ставится на поставщика с уточнением по фабрикам. CSDDD и немецкий LkSG возлагают due diligence на юрлицо-контрагента. Forced Labour Regulation запрещает продукт с конкретного производства. Поэтому нужны оба уровня, и по умолчанию риском считается весь поставщик.

Архитектура

Каталог только для чтения, флаги в SQLite

Данные из CSV не меняются, поэтому при старте каталог загружается в память и больше не трогается. Флаги — единственное, что меняется. Они хранятся в SQLite на Docker volume и не пропадают при перезапуске.

Один клик

Что происходит при нажатии «Flag supplier»

  1. браузер
    Форма отправляет POST /api/suppliers/SUP-002/flags с {factory_ids: ["FAC-0008"], reason, flagged_by}.
  2. nginx
    Проксирует /api в контейнер api. Источник один, поэтому CORS не нужен.
  3. api.py
    Проверяет запрос: поставщик существует (иначе 404), фабрики принадлежат ему и не повторяются (иначе 422), финишер известен (иначе 422).
  4. flags.py
    INSERT. Если у поставщика уже есть активный флаг, unique index бросает IntegrityError, и API отвечает 409.
  5. браузер
    Получает 201 и сбрасывает кэш: от набора флагов зависит каждый экран.
  6. api.py
    Обрабатывает новые GET: evaluate(catalog, active_flags) пересчитывает статусы источников, деталей и игрушек.
  7. UI
    Показывает новые KPI, список затронутых игрушек и трассы с указанием флагнутой фабрики.
Edge cases

Что в данных неровно и как это обработано

D1 · 22 деталиУ одного part_id два поставщикаЭто деталь с несколькими источниками. Если флагнута часть источников, статус potential, и показывается «чистая» альтернатива.
D2 · 5 игрушекУ одного toy_id два финишераЭто общий продукт: BOM общий, цена и объём у каждого финишера свои. Листинг хранится по ключу (toy_id, finisher_id).
D3 · SUP-038Поставщик без фабрикЕго можно флагнуть, экспозиция будет нулевой. Флаг на фабрики для него вернёт 422.
D4 · 26 названий, 53 фабрикиОдинаковые названия фабрикРядом с названием всегда показывается id: «Rayong Plant» FAC-0075 и FAC-0076.
D5 · 6 фабрикНет адреса или городаХранится null, в UI выводится «location unknown», в отчёте info.
parts.supplier_idЛишняя колонкаПоставщик определяется по фабрике. Если колонка расходится с фабрикой, пишется warning, приоритет у фабрики.
re-importФлаг на исчезнувшего поставщикаФлаг не удаляется, а попадает в отчёт Data quality как orphan_flag.
lifecycleИзменить охват флагаСнять флаг и поставить новый. История и аудит остаются честными.
ingestБитые строкиНечисловые значения, кол-во ≤ 0, неизвестные ссылки и дубли: строка пропускается или берётся первая, причина записывается.
Покрыто 78 тестами: правила статусов, каждое правило загрузки, каждая ошибка API, сквозной прогон на реальных данных. Запуск: docker compose up → localhost:8080.
